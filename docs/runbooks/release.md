# Releasing Pult

A release is a `v<version>` tag. The `release` workflow builds everything and attaches it to a Gitea release:

- `pult-<version>-{linux,darwin}-{amd64,arm64}.tar.gz`: `pult` with the catalog built in, plus `README.md` and the licences;
- `pult-<version>-src.tar.gz` (`git archive` of the tag) and `pult-<version>-catalog.db.zst`, for source builds;
- `pult-<version>-SHA256SUMS`;
- `PKGBUILD.pult`, `PKGBUILD.pult-bin` and `pult.rb`, already filled with the version, download URLs and checksums.

All tarballs are reproducible: `scripts/dist.sh` sorts entries, fixes times and owners, and uses `gzip -n`. Data bundles are released separately ([bundle-signing.md](bundle-signing.md)).

## Before the first release (owner)

1. **Public downloads.** The AUR and Homebrew fetch the source tarball and catalog from the release URL. The Gitea repository has been public since 2026-11-07, so release downloads need no login. Only `PatrickFanella` may push `v*` tags (tag protection).
2. **pacman repository.** The release workflow's `arch` job builds `pult` from the release's PKGBUILD and uploads it to the Gitea pacman repository `subcult` (signing key `CCE8 B0F3 BCDD 601D 9097 73E4 466A A6E8 2414 53D2`, generated by Gitea). It needs the repository secret `ARCH_PACKAGE_TOKEN`, a Gitea token with package write access for the organization: the Actions token is refused (`401 reqPackageAccess`), even with the package linked to the repository. Without the secret the job only warns. To publish an existing release, run the `arch-repo` workflow with its version. User setup is in the README.
3. **AUR** (on hold). An AUR account with an SSH key, to create `pult` and `pult-bin`; the release attaches both PKGBUILDs. As of 2026-11 the AUR is not accepting new account registrations, so Arch users use the pacman repository above.
4. **Homebrew tap.** Done 2026-11-12: [subculture-collective/homebrew-tap](https://github.com/subculture-collective/homebrew-tap) on GitHub, with no Gitea copy. Its `update` workflow checks this repository's releases every six hours, then builds, tests and audits the new `pult.rb` on macOS, and commits it only if all three pass. Its `test` workflow runs the same checks on macOS and Linux for every push.
5. **Go.** Nothing to set up. `go install git.subcult.tv/subculture-collective/pult/cmd/pult@<tag>` resolves the tag through proxy.golang.org, and the binary reports the tag as its version. It has no built-in catalog, so users run `pult update` once.
6. **npm.** The release job publishes `@subcult/pult` and one package per platform (`@subcult/pult-linux-x64`, `-linux-arm64`, `-darwin-x64`, `-darwin-arm64`), each holding that platform's binary from the release tarballs; npm installs only the one matching the machine, and the `pult` command is a small Node launcher that runs it. It needs the `@subcult` scope on npmjs.com (an npm organization named `subcult`) and the repository secret `NPM_TOKEN`: a granular access token that may read and write packages in that scope. Without the secret the step only warns. To publish an existing release, run the `npm` workflow with its version.

## Release

```bash
git tag v0.1.0
git push origin v0.1.0
```

Then publish the filled files from the release:

```bash
# AUR, once per package (pult, pult-bin)
git clone ssh://aur@aur.archlinux.org/pult.git aur-pult
cp PKGBUILD.pult aur-pult/PKGBUILD
cd aur-pult && makepkg --printsrcinfo > .SRCINFO && git add PKGBUILD .SRCINFO && git commit -m "Update to 0.1.0" && git push

```

The Homebrew tap updates itself within six hours. To publish sooner, run the tap's `update` workflow by hand (`gh workflow run update --repo subculture-collective/homebrew-tap`).

## Check each channel on a clean machine

Arch, in a throwaway container:

```bash
podman run --rm -it docker.io/library/archlinux:latest sh -c '
  pacman -Sy --noconfirm --needed base-devel git go sudo >/dev/null
  useradd -m b && echo "b ALL=(ALL) NOPASSWD: ALL" > /etc/sudoers.d/b
  su b -c "cd && git clone https://aur.archlinux.org/pult.git && cd pult && makepkg -si --noconfirm"
  pult version && pult search -n 3 catppuccin && pult doctor'
```

macOS: `brew install subculture-collective/tap/pult && pult version && pult doctor` on a Mac (Soyuz, with the owner's approval).

Tarball: download and unpack `pult-<version>-linux-amd64.tar.gz` and run `./pult version`.
